# 企业级 RAG 上传、检索、可信回答与引用设计

## 1. 目标

在不删除、不替换现有上传和聊天接口的前提下，为当前知识库增加以下能力：

- 基于本地磁盘的 2GB 大文件分片上传和断点续传；
- 多关键词、相似度阈值和结果多样性控制；
- 选择知识库时的无依据拒答和引用有效性校验；
- 回答引用列表、文件预览和下载。

新增功能必须复用现有知识库权限、文件处理状态、文档解析、切片、Embedding 和 Qdrant 流程。未选择知识库的普通聊天保持原有行为。

## 2. 兼容原则

- 保留 `POST /api/file/upload`，小文件和旧客户端继续使用原接口。
- 新增分片上传接口，不改变现有 `kb_file` 的处理语义。
- 分片合并成功后才创建 `kb_file`，避免未完成上传进入解析任务。
- 保留现有 SSE 的 `open`、`status`、`message`、`done`、`error` 事件，只增加新的事件。
- 未选择知识库时继续允许模型使用自身知识回答，并保持逐段流式输出。
- 所有新增文件读取、上传、合并、预览和下载操作都执行知识库权限校验。

## 3. 大文件分片上传

### 3.1 参数

- 单文件最大值：2GB，可通过配置覆盖。
- 默认分片大小：10MB，可通过配置覆盖。
- 小于等于 10MB 的文件继续使用现有普通上传。
- 上传会话有效期：24 小时，可通过配置覆盖。

### 3.2 数据模型

新增 `kb_upload_session`：

- `upload_id`：上传会话唯一标识；
- `kb_id`、`create_user`：知识库和上传用户；
- `file_name`、`file_type`、`file_size`：原始文件信息；
- `file_sha256`：前端提供的完整文件摘要，可为空；
- `chunk_size`、`total_chunks`：分片参数；
- `uploaded_chunks`、`uploaded_bytes`：已上传进度；
- `status`：`UPLOADING`、`MERGING`、`COMPLETED`、`CANCELLED`、`FAILED`；
- `error_message`、`expire_time`、`create_time`、`update_time`。

新增 `kb_upload_chunk`：

- `upload_id`、`chunk_index`：联合唯一；
- `chunk_size`、`chunk_sha256`、`file_path`；
- `create_time`。

数据库升级使用独立、可重复执行的 MySQL 5.7 兼容脚本，不改写现有非 UTF-8 初始化脚本。

### 3.3 接口

- `POST /api/file/multipart/init`：校验权限、类型、大小和分片参数，返回 `uploadId`、分片大小和已存在分片。
- `PUT /api/file/multipart/{uploadId}/chunks/{chunkIndex}`：上传单片，支持分片 SHA-256；相同分片重复上传时幂等覆盖。
- `GET /api/file/multipart/{uploadId}`：返回上传状态、已上传分片和字节数，用于恢复上传。
- `POST /api/file/multipart/{uploadId}/complete`：检查全部分片，顺序合并，校验完整文件摘要，创建 `kb_file` 并提交现有处理任务。
- `DELETE /api/file/multipart/{uploadId}`：取消未完成上传并清理临时文件。

### 3.4 磁盘布局与安全

- 临时分片：`${file.upload-dir}/.parts/{uploadId}/{chunkIndex}.part`。
- 合并时先写入同目录临时文件，校验成功后原子移动到正式目录。
- 文件名只作为业务展示字段，磁盘文件名使用 UUID，防止路径穿越和重名覆盖。
- 服务端不信任前端 MIME，继续执行允许类型校验，并校验扩展名与文件类型。
- 合并失败保留可续传分片并记录失败原因；取消和过期清理才删除分片。

### 3.5 前端行为

- 选择文件后，超过 10MB 自动走分片上传。
- 上传前计算完整文件 SHA-256；分片上传时显示已上传字节和百分比。
- 暂停只停止后续请求，不删除上传会话；继续时查询服务端已存在分片并只补传缺片。
- 刷新页面后可从本地保存的 `uploadId` 恢复同一文件上传。
- 合并完成后沿用当前文件处理阶段和重试展示。

## 4. 检索能力增强

### 4.1 检索流程

检索顺序调整为：

1. 查询改写；
2. 查询缓存；
3. 向量候选召回；
4. 多关键词召回；
5. 按 chunk ID 合并去重；
6. 过滤低于相似度阈值的纯向量结果；
7. 向量分数与关键词分数融合；
8. 过滤完全重复和高度相似片段；
9. 返回最终 topK 结果并缓存。

关键词命中的结果允许在向量分数低于阈值时保留，但必须记录为 `KEYWORD` 或 `HYBRID`，避免精确名称和编号被错误过滤。

### 4.2 配置

新增以下可覆盖配置：

- `rag.candidate-k`：候选片段数量；
- `rag.top-k`：最终片段数量，继续兼容原配置；
- `rag.similarity-threshold`：向量最低相似度；
- `rag.vector-weight`、`rag.keyword-weight`：融合权重；
- `rag.diversity-threshold`：相似片段去重阈值。

默认配置以兼容现有召回为准。只有明显低分的纯向量结果和高度重复结果会被过滤。

### 4.3 诊断信息

召回测试返回：

- 原始查询和改写查询；
- 文件 ID、文件名、chunk ID、chunk 序号；
- 向量分数、关键词分数、最终分数；
- `VECTOR`、`KEYWORD`、`HYBRID` 命中方式；
- 是否进入最终上下文以及过滤原因。

## 5. 可信回答控制

### 5.1 生效范围

- `kbId` 为空：完全保持普通聊天行为。
- `kbId` 非空：进入可信知识库回答模式。

### 5.2 无依据拒答

最终检索结果为空时，不调用大模型，直接返回固定结果：

`知识库中没有找到足够依据，暂时无法可靠回答这个问题。`

返回元数据标记 `grounded=false`、`reason=NO_EVIDENCE`，引用列表为空。

### 5.3 引用校验

- 系统提示词要求模型只使用本次检索证据。
- 模型引用格式继续使用 `[来源: 文件名, 第N段]`。
- 服务端从最终答案提取引用，并与本次实际召回的来源逐项比对。
- 只保留能够匹配文件 ID 和 chunk ID 的引用。
- 严格模式下，答案没有任何有效引用时返回固定结果：

`模型未能生成带有效依据的回答，请调整问题后重试。`

该结果标记 `grounded=false`、`reason=INVALID_CITATION`。

### 5.4 流式兼容

- 普通聊天继续逐段推送。
- 知识库严格模式在服务端缓存模型输出，完成引用校验后再通过 `message` 事件发送，避免先展示未经校验的内容。
- 检索期间继续发送 `status` 事件。
- 回答发送前增加 `citation` 事件，回答结束前增加 `answer-meta` 事件。

## 6. 引用展示与文件访问

### 6.1 SSE 数据

`citation` 事件为 JSON 数组，每项包含：

- `fileId`、`fileName`；
- `chunkId`、`chunkIndex`；
- `source`、`contentPreview`；
- `vectorScore`、`keywordScore`、`finalScore`；
- `matchType`。

`answer-meta` 事件包含 `grounded`、`reason` 和有效引用数量。

### 6.2 前端展示

- 回答正文下方显示“参考资料”。
- 每条引用展示文件名、段落序号、命中方式和分数。
- 点击引用打开文件预览接口；浏览器不能内联展示的类型改为下载。
- 不可信回答显示明确状态，不展示空引用容器。

### 6.3 文件接口

- `GET /api/file/{id}/preview`：校验知识库读取权限后以内联方式返回文件。
- `GET /api/file/{id}/download`：校验知识库读取权限后以附件方式返回文件。
- 响应文件名执行 RFC 5987 编码，兼容中文文件名。

## 7. 错误处理

- 上传参数错误返回 400；权限不足返回 403；上传会话不存在返回 404；会话状态冲突返回 409。
- 分片缺失、摘要不一致和文件大小不一致不得创建 `kb_file`。
- 合并、检索、Embedding 和 Qdrant 异常保留现有错误记录方式，不吞掉失败。
- 新增错误信息只返回必要业务信息，不暴露服务器绝对路径。

## 8. 测试与验收

### 8.1 后端自动化测试

- 初始化上传参数和权限；
- 分片幂等上传、缺片拒绝合并、摘要不一致、成功合并；
- 查询进度、取消上传和过期清理；
- 旧上传接口继续工作；
- 多关键词合并、低分过滤、关键词保留和重复片段过滤；
- 无证据不调用模型；
- 有效和无效引用校验；
- 预览、下载权限和文件不存在处理；
- 现有测试全部回归。

### 8.2 前端验证

- 小文件继续普通上传；
- 大文件分片进度、暂停、继续和刷新恢复；
- 回答引用、可信状态、预览和下载；
- 前端生产构建通过。

### 8.3 真实链路验证

- 使用真实 HTTP 请求初始化上传、上传部分分片、查询状态、补传缺片并完成合并；
- 验证合并文件摘要与原文件一致；
- 验证文件进入现有处理状态链路；
- 在外部 Embedding、Qdrant 和模型可用时验证检索、拒答、可信回答和引用事件；
- 外部依赖不可用时明确记录未完成的验证范围，不以构建结果代替运行验证。

## 9. 非目标

本次不引入 MinIO、OSS、消息队列、OCR、文件版本管理、多租户和新的前端 UI 框架，也不修改与知识库功能无关的模块。
