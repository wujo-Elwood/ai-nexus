# 检索、向量重建、知识库清理与部署修复设计

## 目标

修复检索缓存失效后仍可能读取历史版本、Embedding 维度变化后无法重建、知识库删除产生孤儿数据，以及 Docker Compose 首次部署存在的启动竞态。保留当前所有知识库共用一个 Qdrant collection 的架构，不引入多 collection 或双写迁移。

## 向量维度与重建

Qdrant 服务查询 collection 时必须区分“不存在”和“访问失败”。已存在时读取真实向量维度；解析不到维度或访问失败时直接返回明确异常，不能把它当成 collection 不存在后尝试创建。

单知识库重建只用于当前 Embedding 维度与 collection 一致的场景。维度变化时必须执行全局重建：先验证调用者权限并取得新模型实际输出维度，再阻止文件处理和检索写入，删除旧 collection，创建新维度 collection，清除全部旧切片并重新提交所有当前版本文件。全局重建期间向量检索返回明确的“正在重建”错误，避免读取半成品。

全局重建入口放在知识库控制器下的管理接口中，但操作范围和响应文案明确为全部知识库。接口复用现有 RBAC 用户角色查询，只允许拥有启用状态 `admin` 角色的用户触发，避免普通用户重建他人数据。

## 当前版本检索正确性

缓存仍以知识库为粒度主动失效。文件删除、重新处理、上传新版本、版本回滚、知识库删除和全局重建都会触发失效。

从缓存或 Qdrant 获得 chunk ID 后，数据库回查必须同时校验知识库编号、文件为当前版本且处理状态为 `COMPLETED`。Qdrant 中即使保留历史版本向量，也无法进入聊天上下文。版本回滚后清除缓存，下一次检索只接受刚切换为当前版本的文件切片。

## 删除一致性与孤儿清理

知识库删除采用数据库事务内的“先删除知识库记录，再清理关联记录”顺序，使正在运行的后台任务在后续存活校验中停止写入。文件处理在解析后、写切片前、写向量前分别确认知识库和文件仍存在且仍为可处理状态。

Qdrant collection 不存在时，按知识库或文件删除向量视为幂等成功；网络错误和其他服务错误仍阻断数据库删除，避免留下未知状态。

关联清理覆盖：切片、版本快照、标签关联、标签、目录、文件、分片上传记录、分片临时目录、评测用例、评测运行及运行明细、知识质量智能体运行记录、RetrievalCache 和 Qdrant 向量。原始文件删除失败时终止操作并保留数据库记录，避免丢失后续补偿所需路径。

后台任务与删除事务存在跨系统边界，无法依靠单个数据库事务原子覆盖 Qdrant 和磁盘。处理任务通过数据库存活校验停止后续写入；删除操作通过幂等 Qdrant 清理和严格磁盘删除失败处理保证可重试。

## Docker Compose

Ollama 增加健康检查。模型初始化任务等待 Ollama 健康后执行，并在失败时自动重试；后端等待模型初始化成功后再启动。MySQL 和 Qdrant 使用固定的兼容版本，不使用 `latest`，降低一键部署不可重复风险。

Compose 继续保留 MySQL、Qdrant、Ollama、后端和前端五类服务。敏感配置仍通过 `.env` 覆盖，上传目录和三个服务的数据使用持久卷或绑定目录。

## 错误处理

- collection 维度不匹配：返回真实维度、当前模型维度和全局重建操作提示。
- Qdrant 不可访问：返回服务不可用，不能误判为 collection 不存在。
- 全局重建进行中：搜索和普通重建返回明确冲突错误。
- 磁盘文件或临时目录删除失败：知识库删除失败并保留数据库状态，允许修复磁盘权限后重试。
- 异步文件在知识库删除期间运行：存活校验失败后退出，不再插入切片或向量。

## 测试

单元测试覆盖：当前版本回查过滤、Qdrant 404 幂等删除与非 404 失败、真实维度解析失败、同维度单库重建、维度变化全局重建、删除期间异步任务停止、完整关联数据和临时目录清理。

构建验证覆盖：后端全量 Maven 测试、前端生产构建、Compose 配置解析。环境有 Docker 时再执行镜像构建和容器健康检查；没有 Docker 时明确报告未执行项。
