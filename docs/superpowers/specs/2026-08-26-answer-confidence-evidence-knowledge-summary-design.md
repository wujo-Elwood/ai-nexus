# 回答置信度、证据覆盖率与知识摘要设计

## 范围

本次只新增回答置信度、证据覆盖率和知识摘要。自动生成报告不在范围内。

## 方案

聊天服务在可信回答校验后计算回答元数据：置信度为最终引用分数、引用数量和证据状态的加权结果；证据覆盖率按回答句子中存在有效引用标记的比例计算。结果通过现有 SSE `answer-meta` 事件返回，并兼容没有知识库或无证据拒答场景。

知识摘要由知识库洞察页手动触发。后端只读取状态为 `COMPLETED` 的当前版本文件切片，按固定长度分组调用当前激活 LLM 生成分组摘要，再合并为知识库摘要。摘要写入 `kb_knowledge_base.summary` 和 `summary_updated_at`，查询接口直接返回已保存内容；生成失败不覆盖旧摘要。

## 数据与接口

- `kb_knowledge_base.summary`：最新知识摘要。
- `kb_knowledge_base.summary_updated_at`：摘要生成时间。
- `GET /api/kb/{id}/summary`：查询摘要。
- `POST /api/kb/{id}/summary`：重新生成摘要。
- `answer-meta` 增加 `confidence`、`confidenceLevel`、`evidenceCoverage`、`citationCount`、`grounded` 和 `reason`。

## 前端

聊天回答底部显示置信度、证据覆盖率和引用数量；无证据时显示拒答状态。知识库洞察页显示摘要、更新时间和刷新按钮，生成中禁用按钮并保留旧内容。

## 错误处理

- 没有已完成文档时返回明确业务错误，不调用 LLM。
- LLM 生成失败时返回错误，不清空已有摘要。
- 没有引用的普通聊天回答保持兼容，置信度和覆盖率返回 0。
- 摘要内容只来自当前知识库文件，不包含文件路径、密钥等配置。

## 验证

覆盖置信度边界、引用覆盖率、无证据拒答、摘要无文档、摘要成功保存、LLM 失败保留旧摘要、控制器响应和前端构建。
