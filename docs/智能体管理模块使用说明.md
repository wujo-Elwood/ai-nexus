# 智能体管理模块使用说明

## 1. 模块定位

智能体管理模块是平台后续扩展业务智能体的统一入口。它不是简单增加一个按钮，而是把平台已有的知识库、文件、分片、召回、报告能力组织成可以运行、可以保存、可以复盘的智能体任务。

第一期内置一个智能体：知识库质检智能体。

这个智能体的目标是判断一个知识库是否适合用于 RAG 问答，并输出评分、风险、问题、证据和优化建议。

## 2. 设计思路

RAG 平台问答效果不好时，问题不一定出在大模型上，常见原因包括：

1. 文件没有处理完成。
2. 文件解析失败。
3. 分片为空、过短或过长。
4. 重复资料太多。
5. OCR 噪声、目录、页眉页脚污染了分片。
6. 向量召回没有命中。
7. 知识库本身缺少用户会问的资料。

因此第一期没有做复杂的多智能体编排，而是先做最有价值的知识库质检智能体。它用确定性规则先把知识库质量检查清楚，不强依赖大模型，这样结果稳定、成本低，也更容易解释扣分原因。

## 3. 知识库质检智能体检查什么

### 3.1 文件健康度

检查内容：

1. 文件总数。
2. 已完成文件数。
3. 失败文件数。
4. 处理中或待处理文件数。
5. 是否为空知识库。
6. 是否有重复文件名。

### 3.2 分片质量

检查内容：

1. 分片总数。
2. 空分片数量。
3. 过短分片数量。
4. 过长分片数量。
5. 平均分片长度。
6. 最短分片长度。
7. 最长分片长度。
8. 缺少来源信息的分片。
9. 重复分片。
10. 疑似噪声分片。

### 3.3 召回健康度

标准模式和深度模式会执行召回测试。

检查内容：

1. 测试问题是否有召回结果。
2. 召回数量是否太少。
3. 召回来源是否可追溯。
4. 召回片段是否有有效正文。

### 3.4 知识覆盖风险

当前版本使用轻量规则判断覆盖风险：

1. 知识库有描述但没有文件。
2. 有测试问题但知识文件过少。
3. 描述提到合同，但文件名中没有明显合同资料。
4. 描述提到制度，但文件名中没有明显制度资料。

后续版本可以增加大模型分析，让覆盖判断更贴近业务语义。

## 4. 页面怎么使用

进入平台后，顶部菜单会出现：智能体管理。

使用流程：

1. 登录系统。
2. 点击顶部菜单的智能体管理。
3. 找到知识库质检智能体。
4. 点击运行质检。
5. 选择要检查的知识库。
6. 选择检查模式。
7. 可选输入测试问题，一行一个问题。
8. 勾选是否保存本次报告。
9. 点击开始质检。
10. 查看评分、风险等级、问题清单、召回测试和优化建议。

## 5. 检查模式

### 5.1 快速模式

适合日常快速查看。

快速模式检查文件和分片基础质量，不执行召回测试。

### 5.2 标准模式

适合交付前检查。

标准模式会检查文件、分片、重复、噪声，并使用用户输入的测试问题执行召回测试。

### 5.3 深度模式

适合重要知识库验收。

深度模式包含标准模式能力。如果用户没有输入测试问题，系统会基于知识库名称和文件名生成轻量测试问题。

## 6. 报告怎么看

报告分为几部分：

1. 总评分：0 到 100 分。
2. 风险等级：健康、需关注、高风险。
3. 摘要：用一句话说明当前知识库整体状态。
4. 指标：展示文件数、分片数、失败数、空分片、重复分片、召回为空等指标。
5. 问题清单：展示问题级别、问题描述、证据和建议。
6. 召回测试：展示测试问题是否召回、召回数量、来源和片段摘要。
7. 优化建议：按照优先级给出下一步处理动作。

## 7. 评分规则

评分从 100 分开始扣分。

主要扣分项：

1. 空知识库扣 45 分。
2. 失败文件按比例最多扣 20 分。
3. 处理中或待处理文件按比例最多扣 8 分。
4. 没有分片扣 35 分。
5. 空分片按比例最多扣 15 分。
6. 过短分片按比例最多扣 10 分。
7. 过长分片按比例最多扣 10 分。
8. 缺少来源按比例最多扣 10 分。
9. 重复分片按比例最多扣 8 分。
10. 噪声分片按比例最多扣 8 分。
11. 召回为空按比例最多扣 25 分。
12. 召回较弱按比例最多扣 8 分。

风险等级：

1. 85 到 100 分：健康。
2. 70 到 84 分：需关注。
3. 0 到 69 分：高风险。

## 8. 解决了什么问题

这个模块主要解决以下问题：

1. 知识库质量不可见。
2. 上传了文件但不知道是否真的可用于问答。
3. 问答效果差时无法判断是文件问题、分片问题、召回问题还是知识覆盖问题。
4. 文件处理失败容易被忽略。
5. 分片质量没有明确指标。
6. 缺少上线前验收报告。
7. 后续新增智能体没有统一入口。

## 9. 后续可以扩展哪些智能体

后续可以继续加入：

1. 文档入库智能体：自动判断文件类型、推荐知识库、识别解析失败。
2. 召回评测智能体：批量问题评测召回命中率。
3. 文档抽取质检智能体：检查模板字段和抽取结果质量。
4. 合同审查智能体：识别合同风险条款和缺失条款。
5. 报告生成智能体：生成交付报告、审查报告、知识库健康报告。
6. 平台运维智能体：检查模型配置、服务连通性、用量异常。

## 10. 数据库脚本说明

新增脚本：

`database/agent_management.sql`

新增表：

`agent_run`

用途：

保存每次智能体运行记录，包括智能体编码、知识库、检查模式、评分、风险等级、摘要、运行参数和完整报告 JSON。

同时，`database/init.sql` 已追加同样的建表语句，方便全新部署时自动创建表。

## 11. 后端接口说明

### 11.1 获取智能体列表

`GET /api/agents`

返回当前平台支持的智能体。

### 11.2 运行知识库质检

`POST /api/agents/knowledge-quality/run`

请求示例：

```json
{
  "kbId": 1,
  "checkMode": "STANDARD",
  "testQuestions": [
    "这个知识库有哪些核心制度？",
    "请说明合同审批流程"
  ],
  "saveReport": true
}
```

### 11.3 查询运行历史

`GET /api/agents/runs`

可选参数：

`limit`

### 11.4 查询报告详情

`GET /api/agents/runs/{id}`

### 11.5 删除运行记录

`DELETE /api/agents/runs/{id}`

## 13. 使用建议

建议在这些时机运行质检：

1. 新知识库上传完文件后。
2. 文件处理失败后重新处理前后。
3. 调整分片参数后。
4. 更换 embedding 模型后。
5. 项目交付前。
6. 用户反馈问答效果不好时。

如果报告显示高风险，不建议直接把该知识库用于正式问答。应先处理失败文件、空分片、召回为空和知识覆盖不足等问题，再重新运行质检。
